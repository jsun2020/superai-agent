# SuperAI Agent v0.2.23

让本应用像机器上其他软件一样使用操作系统配置的代理，并把 ripgrep 随便携版一起发布。

## 问题修复

- **同一局域网内，Win10 能正常对话而 Win11 收到拦截页**：两台机器同网络、同模型（MiniMax-M3）、同版本，Win10 22H2 两次测试全部成功（打招呼 + 检索出 155 个文件），Win11 24H2 却拿到 v0.2.22 所说的 HTML 拦截页。网络请求路径中**并不存在**任何按操作系统版本分支的代码，真正的差别在于本应用看不到操作系统自己配置的代理。`read_system_ca_env()` 早已把 Windows 根证书导出给 Bun（企业代理重签 TLS 时才能正常握手），但 `read_managed_proxy_env()` 只读取 `~/.claude/superai/settings.json`；在整个仓库中搜索 `ProxyEnable` / `AutoConfigURL` / `winreg` 只有一处命中，且位于第三方类型声明里——**从来没有任何代码读取过系统代理**。于是在 IT 统一配置了代理的机器上，Edge / Office / Teams 都走公司代理，唯独本应用直连，径直撞上透明拦截设备并收到其返回的拦截页；而恰恰是那份根证书导出，让这张拦截页以一个「正常」的 200 响应抵达，而不是报 TLS 错误。

  现在启动 sidecar 时按优先级解析代理：`settings.json`（用户在设置页填写的）> 进程环境中已有的 `HTTPS_PROXY` > **操作系统配置**（`HKCU\...\Internet Settings`）。`ProxyServer` 的两种写法（`host:port` 与 `http=/https=` 列表）均可解析，`ProxyOverride` 会转换为 `NO_PROXY` 且始终包含环回地址（CLI 子进程需要连回 `ws://127.0.0.1`），仅配置 SOCKS 的情况会跳过（Bun 的 fetch 走 HTTP CONNECT，指向 SOCKS 端口只会让报错更难懂）。若系统使用的是自动配置脚本（PAC），环境变量无法表达其规则，程序不会猜测，而是打印该 `AutoConfigURL` 并提示在「设置 → 网络 → 代理」中手动填写。设置 `SUPERAI_USE_SYSTEM_PROXY=0` 可恢复旧行为。

- **代理测试探测了本网络访问不到的域名**：设置页的代理测试原本连接 `www.gstatic.com`——选它是因为企业代理通常放行，但它在本项目所处网络不可达，导致**恰恰在用户最需要这项测试时，一个完全正常的代理被报成故障**。现改为 `open.feishu.cn`（符合项目既有的探测主机规范）。注意该测试通过只能证明代理可达且凭据被接受，并不能证明代理放行了服务商域名——网关完全可以放行飞书却对服务商返回拦截页。

- **便携版在没有装 ripgrep 的机器上 Grep 依然不可用**：v0.2.22 让解析逻辑在随包二进制缺失时回落到 PATH 查找，但这只在机器上本来就有 rg 时才有用，而干净的企业电脑不会有。现在构建脚本会把 rg.exe 放入 `vendor\` 目录（启动时该目录会被前置到 PATH）。ripgrep 版本固定为 14.1.1，压缩包按上游随发布一同公布的 SHA256 校验后才使用，构建因而无法悄悄换成未经审阅的二进制；下载缓存于每次构建时重新校验，被截断或被篡改的缓存会重新下载而不会被打包。MIT 与 Unlicense 许可文本从同一个已校验的压缩包中取出，不再单独联网获取，因此不会与二进制本身脱节。离线或网络受限时可用 `RIPGREP_EXE` 指向本地 rg.exe，`-SkipRipgrep` 可跳过。

## 诊断能力

- 「空响应 / 拦截」类报错现在会附带 `route=` 与 `proxy_source=`，说明这次请求究竟是直连还是走了代理、以及该代理来自设置页、环境变量还是操作系统。这正是「为什么同事的机器可以、我的不行」这一问题所需要的信息，一张截图即可回答。代理地址中的凭据会被隐去。

## 发布流程

- 发布工作流中的 Bun 版本由 `latest` 改为固定版本。v0.2.22 打标签时，Linux-x64 任务因 Bun 1.4.0 恰好在两次发布之间上线而失败（`Target platform 'bun-linux-x64-baseline-v1.4.0' is not available for download`），重跑即通过——发布不应取决于上游在此前几分钟发布了什么。

## 其他说明

- 便携版 zip 与 GitHub Release 安装包同步发布；桌面端「关于 → Check now」可直接从 v0.2.22 升级。
- 本次修复面向 IT 已配置系统代理的机器。若目标机器本身就是直连（与本文开头 Win10 机器相同），说明拦截设备是按策略/网段拦截该机器，此时仍需由 IT 放行服务商域名，本次改动只会让报错更准确。
